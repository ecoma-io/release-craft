# Ecosystem analysis — what release-craft adopted from its siblings

Bootstrap decision record. Before a single file of this repository was
written, two of its siblings were read end to end — `ecoma-io/archkeep` and
`ecoma-io/action-agents`, the org's two most complete TypeScript/Node
repositories — and every practice they carry was classified:

- **ADOPT** — taken as-is, because the reason it exists applies here
  unchanged.
- **ADAPT** — the idea is right for this repository, but its shape here is
  different, and the shape is recorded.
- **REJECT** — deliberately not taken, with the reason, so the question
  answers itself the next time it is asked.

Nothing was copied because the ecosystem has it. Where the two siblings
disagree, the analysis says which way release-craft went and why.

**Scope.** This is a record of Ecoma repository _engineering conventions_ —
provenance, not product documentation. release-craft's product architecture
lives in [`docs/design/`](../design/release-model.md) and the
[ADRs](../adr/0001-domain-kernel-and-semantic-version.md); Ecoma's own use of
the engine is _dogfooding_, a consumer relationship outside the product's
domain ([product boundary](../design/product-boundary.md)).

## Method

- Both repositories were inspected at their default branches: workflows, Moon
  workspace and project graphs, pnpm/package manifests, TypeScript, ESLint,
  Prettier and Vitest configuration, lefthook hooks, commitlint, archkeep
  integration, CI layering, token permissions, caching, pull-request
  validation, issue/PR templates, security tooling, and `AGENTS.md`.
- The classification below is the _input_ to this repository's files, not a
  paraphrase of them: each row names the files here that carry the decision.

## Toolchain

| Decision | What                                                                                                                                     | Why                                                                                                                                                                                                                                                                    |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ADOPT    | pnpm workspaces, `packageManager` pin, `--frozen-lockfile` installs                                                                      | Both siblings pin pnpm and never install unlocked; drift is a policy failure here too (`scripts/check-package-contract.mjs`).                                                                                                                                          |
| ADOPT    | TypeScript `strict` baseline with the exactness flags (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`) | archkeep's baseline verbatim; it cost nothing to adopt and catches real drift.                                                                                                                                                                                         |
| ADOPT    | ESLint flat config, `strictTypeChecked` + `projectService`, `eslint-config-prettier` last, `@vitest/eslint-plugin` for tests             | The org has one ESLint posture; carrying a second would be a parallel convention.                                                                                                                                                                                      |
| ADOPT    | Vitest with `passWithNoTests: false` and coverage thresholds enforced from the first commit                                              | A coverage gate that only turns on "when there is enough code" never turns on. Both siblings set thresholds before there was anything to cover.                                                                                                                        |
| ADOPT    | lefthook: pre-commit fast checks only (format, lint, policy), pre-push tests, commit-msg commitlint                                      | archkeep's split. Slow checks in pre-commit teach people to bypass hooks; here pre-commit stays under a couple of seconds.                                                                                                                                             |
| ADOPT    | commitlint `config-conventional`                                                                                                         | Conventional Commits is the org-wide subject grammar; the squash commit's subject is the PR title, enforced in CI.                                                                                                                                                     |
| ADAPT    | Moonrepo `vcs.provider`                                                                                                                  | archkeep uses `github`; release-craft sets `provider: other` with `defaultBranch: main`. `github` mode makes Moon query the GitHub API during affected detection — needless network coupling in a repo whose CI runs offline-safe.                                     |
| ADAPT    | Moon tags                                                                                                                                | Both siblings namespace with colons (`type:package`). Moon refuses colons in tags — release-craft writes `type-package`/`type-gates` (dash form), the same vocabulary without the error.                                                                               |
| REJECT   | A `packages/` layout for a workspace of one                                                                                              | action-agents splits `apps/`+`packages/`. release-craft has exactly one shippable package and one gate-scripts project; a directory hierarchy that encodes a distinction with one member each is ceremony. The Moon map in `.moon/workspace.yml` says who lives where. |
| REJECT   | Turborepo / Nx                                                                                                                           | The org standard is Moon. Nothing here needs a second graph format.                                                                                                                                                                                                    |

## Task graph

| Decision | What                                                                                                                                     | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ADOPT    | One canonical task name per gate (`format`, `lint`, `typecheck`, `test`, `build`, `arch`) in every project, plus a per-project aggregate | `moon run ...:lint` then means the same thing in any org repo; scripts in package.json are thin wrappers over Moon, not a second graph.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ADOPT    | Explicit `inputs:` on every task                                                                                                         | Moon's default inputs are the project's own files; a task whose real inputs live elsewhere silently stops running when those change. Cross-project files are declared as v2 `project://id?group=` URIs — measured, the tilde forms (`~project/**/*`) hash as literal paths that never invalidate, and the URI form requires a `dependsOn` edge, which the boundary law refuses between package and gates. The workspace-wide tasks (format, format-check, arch, the root lint) therefore disable caching rather than serve a verdict from inputs Moon cannot fully name. |
| ADOPT    | `options: cache: false` on the one side-effecting task (`format`)                                                                        | Cached side effects are how a formatter appears to pass while doing nothing; archkeep carries the same carve-out with the same comment.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ADOPT    | Explicit project map in `.moon/workspace.yml` (`release-craft`, `gate-scripts`, and since the domain kernel, `core-domain`)              | archkeep's convention — and it is what gives this repo a real module boundary on day one: the gate scripts cannot import the package they are policing, the kernel cannot import anything at all, and the canary tests proved both boundaries bite.                                                                                                                                                                                                                                                                                                                      |
| ADAPT    | Aggregate gate                                                                                                                           | archkeep has one `check` task per project. release-craft also exposes `pnpm check` composing all gates including `arch`, because "the repository is correct" is a single claim a human should be able to make with one command.                                                                                                                                                                                                                                                                                                                                          |

## Architecture governance

| Decision | What                                                                                                        | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ADOPT    | archkeep as the boundary governor, run through Moon (`release-craft:arch`) and as its own required CI check | The org gates every repository with archkeep; release-craft is no exception. The devDependency is pinned **exact** (`0.24.1`, no caret): the governor's own drift must never be silent. Renovate's override gives it `minimumReleaseAge: 0` so that pin moves the day a release ships.                                                                                                                                                                                                     |
| ADAPT    | The configuration file                                                                                      | `archkeep.json` at the workspace root **hard-errors** in a Moon-provider workspace (`.moon/` present) — both siblings carry that comment next to the file they deliberately do not have. release-craft uses the Moon provider's by-convention file: `module-boundaries.config.mjs`, exporting `depConstraints`, `moduleBoundaryOptions` (all eight defaults written out) and `boundarySuppressions` (kept empty; a suppression needs a reason, and the honest count at bootstrap is zero). |
| ADOPT    | Exit-code honesty                                                                                           | archkeep exits `0` clean · `1` findings · `2` usage · `3` no-verdict. The CI `arch` job fails on anything but `0` — a verdict that could not be reached is never a clean tree.                                                                                                                                                                                                                                                                                                             |
| ADOPT    | The negative test before shipping the boundary                                                              | Both siblings document the fail-open resolver problem (a boundary over a graph Moon has not populated reports no findings). release-craft proved its boundary bites before the init commit: a canary import from `gate-scripts` into the package made `pnpm arch` exit non-zero, then the canary was removed and the tree re-verified clean.                                                                                                                                               |

## CI layering

| Decision | What                                                                                                                                                | Why                                                                                                                                                                                                                                                                                                    |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ADOPT    | Three workflows, three questions: `ci.yml` (is the change correct), `analysis.yml` (is the repository healthy), `policy.yml` (does governance hold) | Not a god workflow: the three questions change on different cadences and fail for different reasons.                                                                                                                                                                                                   |
| ADOPT    | Required status checks as individual canonical gates, one per question, plus a stable aggregate gate                                                | Six jobs named exactly `format`, `lint`, `typecheck`, `test`, `build`, `arch` so the ruleset requires names a human wrote, and `ci-gate` as the aggregate.                                                                                                                                             |
| ADOPT    | The inverted gate guard                                                                                                                             | `ci-gate`/`analysis-gate` assert every `needs.*.result` **equals** `success` and fail on an empty list. The org measured the alternative: a deny-list guard (`!contains(...)`) reported green over a red pipeline when an outage delivered _no_ results. Allow-list, run unconditionally, fail closed. |
| ADOPT    | `moon ci --base` on pull requests, `moon run` on the default branch, `fetch-depth: 0`, `MOON_BASE` from the PR base SHA                             | archkeep's pattern verbatim. On a docs-only PR the empty result is the graph's claim, not skipped work.                                                                                                                                                                                                |
| ADOPT    | Unfiltered `pull_request:` trigger                                                                                                                  | A `branches: [main]` filter skips required checks entirely on stacked PRs — a pending-forever block. Both siblings learned this the same way.                                                                                                                                                          |
| ADOPT    | Concurrency groups with `cancel-in-progress` on PRs only                                                                                            | Cancellng a `main` push hides which commit went red.                                                                                                                                                                                                                                                   |
| ADOPT    | PR title commitlint in CI (title through `env`, never `${{ }}` into the script)                                                                     | The squash subject is the PR title; it is the one commit message the commit-msg hook never sees.                                                                                                                                                                                                       |
| REJECT   | Merge queue (`merge_group` triggers) at bootstrap                                                                                                   | Nothing here merges fast enough to need one, and its ruleset wiring is one more thing to verify on day one. Deferred with the ruleset change that would introduce it.                                                                                                                                  |

## Workflow security

| Decision | What                                                                                                                                      | Why                                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ADOPT    | Full 40-character SHA pinning of every `uses:`, with the version kept as a comment                                                        | A movable tag is a supply-chain injection waiting for its day; the comment keeps the digest reviewable. `scripts/check-workflow-safety.mjs` makes the convention executable — every future workflow is scanned for it.                                                                                                                                                                                                  |
| ADOPT    | `permissions` declared at the top level (`contents: read` or `read-all`), widened per job, `persist-credentials: false` on every checkout | No `write-all` anywhere; a job-level block replaces the workflow-level one, so analysis jobs restate `contents: read`. Both siblings carry the same posture.                                                                                                                                                                                                                                                            |
| ADOPT    | No `pull_request_target`                                                                                                                  | Arbitrary PR code with write credentials is the bootstrap invariant the whole design protects; the policy gate scans for it in every workflow.                                                                                                                                                                                                                                                                          |
| ADOPT    | Secrets through `env:`, never `${{ secrets.* }}` interpolated into `run:`                                                                 | Interpolation pastes the value into shell source; a crafted branch name or title is code. Enforced by the same policy script.                                                                                                                                                                                                                                                                                           |
| ADOPT    | CodeQL, both legs (`javascript-typescript` + `actions`), and Gitleaks over full history                                                   | The `actions` leg matters most here: this repository's workflows are its product surface — every org repo copies from them.                                                                                                                                                                                                                                                                                             |
| ADAPT    | Semgrep                                                                                                                                   | archkeep and action-agents block on their **own** fixture-tested rule sets. release-craft has no rules of its own at bootstrap, and a registry pack can gain a failing rule overnight — so registry packs (`p/javascript`, `p/github-actions`) run **report-only** via SARIF, the blocking teeth stay with CodeQL and Gitleaks, and the org's own rules arrive in a reviewed PR once this repo has rules worth testing. |
| ADAPT    | Gitleaks invocation                                                                                                                       | Driven as the checksummed OSS binary, not `gitleaks/gitleaks-action` (the wrapper demands a license key for organization-owned repos and dies red on fork PRs before scanning anything). Exit contract kept: `0` clean, `2` leaks, anything else an incomplete scan that fails loudly.                                                                                                                                  |

## Repository policy as executable gates

| Decision | What                                                                     | Why                                                                                                                                                                                                                                                                                                                    |
| -------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ADOPT    | The idea, from action-agents: governance that runs, not prose that hopes | The four gates in `scripts/check-*.mjs` (required/forbidden files, package contract, workflow safety, documentation integrity) are action-agents' premise applied to a bootstrap: every invariant this document could assert about the repository is asserted by a script with tests, run locally and in `policy.yml`. |
| ADAPT    | Scope                                                                    | action-agents writes general-purpose triage actions; release-craft's four gates are this repository's own contract (its file list, its package identity, its workflow posture, its docs). They ship with node:test suites that prove each rule fires on the drift it exists to catch.                                  |
| REJECT   | CODEOWNERS at bootstrap                                                  | One owner; a file mapping one account to every path states no information. Deferred until a second maintainer exists.                                                                                                                                                                                                  |

## Documentation and templates

| Decision | What                                                                                                                        | Why                                                                                                                                                                                                                                                                                                                     |
| -------- | --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ADOPT    | `AGENTS.md` as the operational contract (imported by `CLAUDE.md`), status-honest `README.md`, flow-shaped `CONTRIBUTING.md` | Org convention in both siblings: agents read `AGENTS.md` first; the README states what exists, never what is planned as if shipped.                                                                                                                                                                                     |
| ADAPT    | Issue forms                                                                                                                 | The `bug: ` / `needs triage` frontmatter and the observed-vs-inferred discipline carry over; the form's area dropdown is this repository's surface (toolchain, CI, policy gates, Moon graph, boundary, docs). YAML forms are reproduced as markdown when filed through the API — the org rule, restated in `AGENTS.md`. |
| ADOPT    | The docs-integrity gate                                                                                                     | Neither sibling had one; both wanted one. Broken relative links, anchors that do not resolve, and documented `pnpm <command>`s that are not scripts are exactly the rot a bootstrap accrues silently — release-craft starts with the gate on.                                                                           |
