# Phase decision log — the orchestrator's working record

This file is the coordination log for the phased construction of the release
engine ([#13](https://github.com/ecoma-io/release-craft/issues/13)). It records
the state of architectural thinking as it moves: the current hypothesis, what is
settled, what is deliberately still open, what was rejected, and what each
workstream depends on. Decisions that survive review are promoted into ADRs;
this log keeps the trail that led there — including the trails that dead-ended.

Rules for this file:

- One row per decision, with the evidence that justified it.
- Nothing is deleted when it is rejected — it moves to "Rejected alternatives"
  with the reason.
- Vocabulary changes are never silent: any term redefined here must be reflected
  in the scenario matrix before Phase 1 implements it.

## Current architecture hypothesis

**Decided (2026-09-05, decision D4).** The release model is
**Model C′ = Model C + amendments A1–A7** — a release is the stateful
execution of a _Release Plan_ on a _release line_, with planning and execution
as separate domains. The full definition, vocabulary lock, invariants, and
complexity budget are recorded in `release-model.md` and ADR-0002, which
survived the adversarial design review; the decision and its evidence are
recorded under D4 below.

Candidate mental models that were evaluated:

- **Model A** — a release is a version-on-branch concept. **Rejected.**
- **Model B** — a release is a linear pipeline. **Rejected.**
- **Model C** — a release is the stateful execution of a _Release Plan_.
  **Survives with amendments → adopted as C′.**

## Carried obligations (from the Phase 1 adversarial review, D9)

Findings accepted as correct-as-is or deferred, recorded so they are not
re-litigated and not missed by the phase that owns them:

- **Empty groups are decision records, never mints (Phase 2).** The planner
  converts `ChangeSet.empty()` into a `no-op`/withheld decision record
  (PL-06, S-01 — the latent version is minted nowhere) and never derives a
  version from the empty group's neutral `"patch"`. Construction-time
  rejections (`InvalidChangeSetError` and kin) surface as decision records
  at the planning boundary too — invariant 4's "never an exception" clause,
  re-worded in `release-model.md` to reconcile PL-01's "an error".
- **The prerelease-pointer convention is Phase 2 line policy.** M-08 moves
  the released pointer to a prerelease; P-02/P-07 publish streams with the
  pointer silent. The kernel records either; the planner picks one and
  records it, and must resolve P-02's ladder-override branch, which
  publishes a version that sorts below the pointer and therefore cannot
  move it (the kernel's highest-by-precedence reading).
- **M-01 needs an invariant home (Phase 2 contract).** Line attribution by
  ancestry with fail-closed refusal is the planner's first job and no
  invariant's stress list names it; the Phase 2 contract either adds it to
  invariant 4's stress list or extends invariant 6's sentence.
- **PL-04's self-reference exclusion needs a named rule (Phase 2 contract).**
  The planner's own bookkeeping commits must be deterministically
  identified and never auto-classified as release input; no invariant
  sentence carries it yet (fork 8 adjacent).
- **Plan supersession may terminate in a decision record (Phase 2).** A
  regeneration that lands on PL-06 emptiness closes an open plan with a
  no-op successor — invariant 5's recorded relation must admit mixed-kind
  endpoints.
- **Invariant 10's final clause tightens at the execution contract.**
  "Never publishes new bytes under an existing version identity" becomes
  "never publishes _unrecorded_ new bytes" — PR-02's deliberate rebuild,
  recorded as a new generation, is the sanctioned escape the invariant's
  own generation clause already implies.
- **Kernel values are projections of tag history (Phase 2 loader).** The
  loader rebuilds line/channel values from tags at plan time; stored values
  are caches, never a second source of truth (invariant 6 × invariant 8 ×
  E-11's execute-time re-read).
- **Nightly would widen the kernel (fork 15, only if resolved line-side).**
  `1.5.0-nightly.20260905.abc123` is a valid `Version` but not a
  `PrereleaseStreamState` (non-numeric position); adopting nightly as a
  line release is an ADR-0002 vocabulary amendment, never a silent field.
  Per-stream lifecycle (P-02 "open/completed", P-05 "orphaned") stays
  policy data over the value's keys.
- **The change→released-versions relation has no vocabulary term (only if
  persisted).** M-03/M-04/M-06/M-09 need it as planning-side data
  recomputable from tags; persisting it under a new name requires an
  ADR-0002 amendment. Invariant 1's clause list and §5's S-01/S-04 split,
  invariant 9's "identity matching over recorded provenance" phrasing
  (M-05's consume-lineage decision is planning-side), and `Bump`'s
  provenance note for ADR-0002's vocabulary table are recorded wording
  observations only.
